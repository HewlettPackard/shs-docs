|3985188|CXI Provider: dangling fabric pointer after fi\_close|Fixed a CXI provider issue that could cause Open MPI to access invalid memory during startup. The problem happened when one Open MPI component opened a CXI fabric, failed to create a domain, and closed the fabric. A second component could then get a reference to that closed fabric from libfabric. Domain-creation failures now clean up the fabric correctly, so a closed fabric is never handed out again. This only occurs in an uncommon case: `fi\_domain` fails when `default\_rgroup\_id` is 0|libfabric|SHS v14.0.0|
|3984756|prov/cxi: Segmentation Fault with FI\_MATCH\_COMPLETE and FI\_COMPLETION Flags on Small Message Transfers|Fixed a CXI provider issue that could corrupt a queue and crash an application with a segmentation fault. It affected small messages sent with FI\_MATCH\_COMPLETE and FI\_COMPLETION. When a message landed on the target's overflow list, the target could send back more than one completion response. Each response could remove and free the same send request, so the request was freed more than once. The provider now removes the send request only when the last response arrives. Before this fix, affected MPI jobs could see communication failures, become unstable, or end unexpectedly.|libfabric|SHS 14.0|
|3981938|kcxi Rejects Invalid Out-of-Range NIC Addresses During Node Resolution|Added validation to reject out-of-range NIC addresses during node string resolution, preventing invalid hexadecimal values from being interpreted as error codes and avoiding potential kernel crashes.|kfabric|SHS v14.0.1|
|3972758|KFI LND Target PUT During Rollback Can Trigger Panic Due to Missing RX Request Mapping|Resolved a kfabric panic that could occur during rollback when processing a target PUT event after RX buffer mappings had been removed. RX context teardown now invalidates posted receive LEs and flushes pending CQ work before RX descriptors are unmapped, ensuring queued events are processed safely and preventing NULL request access.|kfabric|SHS v13.1.0|

|3869164|Libfabric: Fix Missing Runtime Library Path for fi\_info|Resolved an issue where the fi\_info utility could fail to start due to missing runtime library path information, resulting in libfabric.so.1 load errors. |3835234|Network Configuration: Improve slingshot-ifroute validation and multi-HSN route handling|Fixed two slingshot-ifroute issues that could make the service fail and leave HSN interfaces unreachable:<br>  <br>  VLAN interfaces flagged as duplicates: A physical HSN interface and its VLAN interface can validly share the same routing table ID. Starting in SHS 13.1, `slingshot-ifroute` treated this setup as a duplicate and failed with `Multiple entries found for rt\_hsn0 in /etc/iproute2/rt\_tables`. These mappings are now handled correctly.<br>  <br>  `post-up` read as an interface name on CSM systems: `slingshot-ifroute` did not check its interface arguments. When it received `post-up`, it created an unwanted `rt\_post-up` routing table entry, and that entry's table ID could conflict with the valid `rt\_hsn0` entry. Invalid interface arguments like `post-up` are now rejected.|environment/sys config|SHS v14.0.0|
